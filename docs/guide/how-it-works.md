# 生成原理

把原图缩成 N×N 个格子，每格取平均色，再从方块里找肉眼看起来最接近的那一块。效果好坏，主要看「最接近」怎么算。

## 为什么不能直接比 RGB

两个颜色在 RGB 里的距离，和人眼感受到的差别不是一回事。最明显的是绿色：RGB 里差很多的两个绿，人眼几乎分不出来；蓝色稍偏一点，一眼就能看出。

所以匹配分两步：先按人眼感知筛出一小撮候选，再对候选逐个算色差，取最小的那个。这样同样的方块集合能挤出更连续的色阶，人像肤色不容易突然跳一档，也不会整片偏灰。

## 方块代表什么颜色

每个方块用一个平均色参与匹配，来自 16×16 原版贴图的逐像素平均，而不是贴图里的某一个像素。

带纹理的方块（圆石、砖块）平均下来会偏灰。想让画面更有质感，可以打开「方块质感」，它给每格加一圈明暗边——只影响预览，不改匹配结果。

贴图本身也只用于预览：画布上看得到真实材质，导出的施工图始终是纯色，因为施工图要的是看得清。

## 采样

原图先居中裁成正方形，不拉伸变形，再按目标格数分块取样。每块内的像素按面积加权平均，缩小时不丢细节、放大时不漏小元素；全透明的格子保留为空格，logo 的镂空能留住。

## 抖动：什么时候开

抖动用噪点换更自然的渐变，算法和强度都能自己调：

- Floyd–Steinberg：误差扩散，渐变最自然，照片常用
- Atkinson：噪点更少，纯色区更干净
- Bayer 4×4 / 8×8：规则点阵，适合像素字与 logo 的渐变

它解决的是方块颜色档位不够的问题：天空只有三四种蓝，直接匹配会出现生硬的色带，抖动后看起来像连续渐变。代价是大面积纯色区会出现噪点，所以默认关闭。什么时候值得开：渐变占比大、画幅 ≥ 96 的图像。

## 去杂点

如果一个格子和上下左右四个邻居都不同，但颜色又很接近其中某一个，就把它并过去。这样能消掉照片噪点造成的零星孤岛，同时保住眼睛和高光这类真正需要对比的地方。

它和抖动是反向操作：抖动制造噪点，去杂点消除噪点。两个一起开通常没意义。

## 手画的格子

换方案、换画幅、重新生成时，手画过的格子都会盖回去，不会被覆盖。改了画幅则例外——旧网格的坐标对不上新网格，手画内容会被清掉。
