# 地图画与地图数据

[地图画生成器](../tools/map-art)做的是另一条产品线：不摆方块，而是把一张 128×128 的图
**直接写进存档的地图数据文件**，再用 `give` 指令拿一张指向它的地图物品。

它和[方块像素画生成器](../tools/pixel)的区别：

| | 方块像素画 | 地图画 |
| --- | --- | --- |
| 放进游戏的东西 | 结构方块 `.nbt`，要真的盖出来 | `map_<#>.dat`，替换存档数据 |
| 画幅 | 16–160 格自由，超 48 自动分块 | 固定 128×128，一张地图刚好 |
| 调色板 | 142 种方块的平均色 | 61 种地图基础色 × 4 档明暗 = 244 色 |
| 施工 | 需要按图纸摆方块 | 不需要摆方块；想摆也可以，但只能还原平面 61 色 |

## 一个像素就是一个字节

地图的 `colors` 是长度固定 **16384**（128×128）的字节数组。每个字节拆成两部分：

```
色号 = 基础色 ID × 4 + 明暗档位
```

基础色 0 是「未探索」，四档都是透明，所以实际可用色号是 4 ~ 247。四档乘数
`180 / 220 / 255 / 135` 不是从亮到暗排的：**档 2（255）是方块原色，档 3（135）最暗**。

游戏自己生成地图时只用得到前三档（靠相邻方块的高度差决定明暗），第四档要靠外部工具写文件。
因为这个工具是直接写地图数据，四档都能用；如果哪天想真的平铺摆出来，把「可用色阶」
切成「仅平面 61 色」，导出的就都是能落地的颜色。

## 颜色怎么选、怎么抖

- **采样**：平滑模式按网格做 alpha 加权平均，适合照片；像素模式先最近邻取样，保留像素画的硬边。
  对比度、饱和度沿用方块画生成器那套 `sampleGrid`，不在地图画里重写一遍公式。
- **色差**：用 `core/color.ts` 的 CIEDE2000（Lab 粗筛 + 精算），比在 RGB 上量距离更贴人眼。
- **抖动**：默认 Floyd–Steinberg 误差扩散，蛇形扫描减少单向纹理，强度可调；
  也有 Bayer 4×4 有序抖动，结果确定、不积累噪点；不想要噪点就关掉。
- **透明**：alpha < 128 的格子写成色号 0，地图上显示为未探索；也可以填白 / 填黑。

预览里给的平均 ΔE 是原图色与选中地图色的 CIEDE2000 均值，调参数时可以直接看这个数变小没有。

## 导出四种东西

| 产物 | 用途 |
| --- | --- |
| `map_<#>.dat` / `<#>.dat` | gzip 压缩的 NBT，放进存档的核心文件 |
| ZIP 说明包 | 地图文件 + `使用说明.txt`，含分版本路径与编号注意事项 |
| `give` 指令 | 复制后进游戏聊天栏粘贴，拿到指向该编号的地图物品 |
| PNG 预览 | 128×128 逐像素对照图，透明区域是透明的 |

`.dat` 里的字段：`data` compound 下有 `scale`（固定 0）、`dimension`、`xCenter` / `zCenter`、
`locked`（默认 1，防止游戏按地形重绘覆盖）、`trackingPosition`、`unlimitedTracking`、
空的 `banners` / `frames`、16384 字节 `colors`；根一层还有 `DataVersion`。
`scale` 必须留 0——放大只会让一个像素覆盖更多方块，把画抹掉。

## 版本差异是最容易踩的坑

| 游戏版本 | 地图文件位置 | 计数文件 | `give` 写法 |
| --- | --- | --- | --- |
| 1.20.4 | `存档/data/map_<#>.dat` | `data/idcounts.dat` | `filled_map{map:<#>}` |
| 1.21 ~ 1.21.11 | `存档/data/map_<#>.dat` | `data/idcounts.dat` | `filled_map[minecraft:map_id=<#>]` |
| 26.1 及以上 | `存档/data/minecraft/maps/<#>.dat` | `data/minecraft/maps/last_id.dat` | `filled_map[minecraft:map_id=<#>]` |

26.1 重排了整个存档目录：地图挪进带命名空间的子目录，文件名去掉 `map_` 前缀，
`idcounts.dat` 改名 `last_id.dat`。工具里的版本选择会同时决定 `DataVersion`、文件路径、
ZIP 里的文件名和 `give` 语法，选错版本文件就放不进去。

**编号不要乱填**：存档用计数文件记着「最新地图编号」。编号与已有地图冲突会直接覆盖它；
编号比记录值还大时，游戏下次发新地图仍从小编号排，可能反过来把你放进来的文件覆盖掉。
最稳的做法是先在游戏里用空地图画一张，看它拿到几号，再回到工具用那个编号重新导出替换。

## 数据来源

- 地图基础色表、明暗系数、`.dat` 的 NBT 结构、DataVersion：Minecraft Wiki
  （Map item format / Data version / Java Edition level format）
- 26.1 的存档目录调整：Minecraft Wiki「Java Edition level format」的 26.1 snapshot 6 条目
- 算法是公开的：CIEDE2000（Sharma 等，2005）、Floyd–Steinberg（1976）、Bayer 有序抖动。
  参考了 SlopeCraft / mapartcraft 一类开源项目的算法选型，实现是本项目自己写的，没有复制第三方代码

## 常见问题

**能导出立体地图画（阶梯式）吗？** 现在不能。那需要把明暗档位反推成高度差，
再生成方块施工图，是另一套投影逻辑。这个工具只做「把图写进地图物品」。

**地图放进去了但游戏里是空白？** 先确认三件事：文件位置和版本对不对、编号与 `give` 指令一致、
进游戏前有没有退出存档（游戏运行时会把它自己的内存数据写回来覆盖）。

**支持基岩版吗？** 不支持，地图数据格式与命令都不同。
