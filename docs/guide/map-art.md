# 地图画与地图数据

[地图画生成器](../tools/map-art)有三种产出路线：**直接写地图数据**（不用摆方块）、
**平铺摆方块**、**立体阶梯摆方块**。前者的产物是存档里的地图数据文件，后两者还会
额外给出可以直接载入游戏的施工文件。

它和[方块像素画生成器](../tools/pixel)的区别：

| | 方块像素画 | 地图画 |
| --- | --- | --- |
| 放进游戏的东西 | 结构方块 `.nbt`，要真的盖出来 | `map_<#>.dat`，或地图色对应的方块施工图 |
| 画幅 | 16–160 格自由，超 48 自动分块 | 固定 128×128，一张地图刚好 |
| 调色板 | 142 种方块的平均色 | 61 种地图基础色 × 4 档明暗 = 244 色 |
| 色差 | Lab 粗筛 + CIEDE2000 | 同一套 CIEDE2000，误差在线性光里扩散 |

## 一个像素就是一个字节

地图的 `colors` 是长度固定 **16384**（128×128）的字节数组。每个字节拆成两部分：

```
色号 = 基础色 ID × 4 + 明暗档位
```

基础色 0 是「未探索」，四档都是透明，所以实际可用色号是 4 ~ 247。四档乘数
`180 / 220 / 255 / 135` 不是从亮到暗排的：**档 3（135）最暗**。

关键是：**明暗档不是颜色属性，是高度差**。中文 Minecraft Wiki 给的例子很直白——
两块南北相邻的黑色羊毛（基础色 25,25,25）：

| 当前格与北侧格的高度 | 乘数 | 档位 | 地图上的颜色 |
| --- | --- | --- | --- |
| 比北侧**低** | 180 | 0 | 17,17,17 |
| **同高** | 220 | 1 | 21,21,21 |
| 比北侧**高** | 255 | 2 | 25,25,25 |

第 4 档（135）只在深水处出现，摆方块拿不到，只有直接写 `.dat` 才能用。
所以三种模式可用的颜色数是不同的：

| 模式 | 可用档位 | 颜色数 | 说明 |
| --- | --- | --- | --- |
| 地图数据 | 0 / 1 / 2 / 3 | 244 | 不摆方块，四档直接写进文件 |
| 平铺 | 只有 1 | 59 | 全部同高；59 = 61 减去两种摆不出来的基础色 |
| 立体阶梯 | 0 / 1 / 2 | 177 | 靠逐行升降切换前三档 |

> 这里修过一个真实的错误：早期版本把「平铺」当成 255 档（原色），
> 实际平铺同高只出 **220 档**。用错档位会让导出的施工图和地图数据对不上。

## 哪些颜色摆得出来

方块与地图基础色的对应关系来自 [plonck/palette](https://github.com/plonck/palette)（MIT）
从 1.21.11 客户端导出的 `blocks.csv`，逐条核对过。工具给每个基础色挑了一个
实心整方块、无重力、不会自行融化或枯萎、生存拿得到的代表方块；同色有便宜方块时
不选贵重方块（例如 31 号 DIAMOND 色用海晶石砖，不用钻石块）。

只有两种基础色摆不出来，**7 号 PLANT** 只有树叶与花草、**12 号 WATER** 只有水与水生植物，
所以摆方块的色板会把它们排除，避免生成一张游戏里根本做不出的图。

## 立体阶梯怎么算

明暗档只取决于**同一列里、北侧那一格**的高度差符号，列与列互不干涉：

```
档 0 → 当前格比北侧低 → 高度 -1
档 1 → 同高            → 高度不变
档 2 → 当前格比北侧高 → 高度 +1
```

从地图最北端开始逐行累积即可得到高度图。两个容易踩的点：

- **noobline**：最北侧那一行没有「北侧方块」，游戏会拿地图外的地形来比。
  工具会在地图边界外多铺一行（社区叫 noobline），把第一行的档位固定下来。
- **基准高度**：高度差只比符号、不比大小，所以每一列都可以整体平移。
  工具默认**逐列**把最低点对齐到 0（noobline 逐列取不同高度），支撑方块最少；
  关掉「高度压缩」则全图共用一个基准，回到经典阶梯，通常会更高、更费方块。
  （试过在下降步一次多降几格来「压缩」，归一化后跨度反而更大，已放弃。）

预览里可以切到「高度图」视图核对起伏，统计栏会给出总层数、总方块数与支撑方块数。

## 施工文件

摆方块的两种模式会多出两个下载项：

| 文件 | 用途 |
| --- | --- |
| `.litematic` | Litematica 投影，Version 6 格式，一个 Region 装下整幅图，含顶层方块、支撑方块与 noobline |
| 分块 `.nbt` ZIP | 按结构方块 48³ 上限切成若干块，包内 `摆放说明.txt` 写明每块的相对位置 |

两种导出共用同一份「某坐标摆什么」的取块函数，不会出现投影对、结构文件差一格的情况。
每根柱子从基准面往上填廉价支撑方块，最顶上那一格才是决定地图色的方块；
支撑方块可以在参数里换成泥土 / 圆石 / 石头 / 橡木木板。

`.litematic` 我们额外用独立的 [litemapy](https://pypi.org/project/litemapy/) 做过
18 万体素的逐格比对，确认位打包、下标顺序与调色板都对。

## 生成质量

- **颜色匹配**：复用 `core/color.ts` 的两段式 CIEDE2000（Lab 粗筛 + 精算）。
- **线性光误差扩散**：Floyd–Steinberg / Atkinson 的误差在**线性光**里传播，
  而不是在 gamma 编码的 sRGB 数值上。暗部渐变不会发脏、亮部不会过冲；
  蛇形扫描减少单向纹理，强度可调。
- **五种抖动**：无 / Floyd–Steinberg / Atkinson（噪点最少）/ Bayer 4×4 / Bayer 8×8。
  有序抖动是确定性的、不积累误差；照片适合误差扩散，像素字与 logo 适合关掉。
- **去孤立噪点**：只在四邻全不同色、周围至少三格同属另一色、且那颜色与原图
  的 CIEDE2000 差很小时才归并，不会把眼睛高光和边缘过渡抹掉。
- **采样**：平滑模式按网格做 alpha 加权平均；像素模式先最近邻取点保留硬边。
  透明像素在游戏里是「未探索」，摆方块时会打断高度链，所以自动填白（也可选黑底）。
- **质量指标**：预览下方给平均 ΔE（原图与选中地图色的 CIEDE2000 均值），
  调参数时可以直接看这个数有没有变小。

## 地图数据与版本差异

`map_<#>.dat` 的 `data` compound 里有 `scale`（固定 0）、`dimension`、
`xCenter` / `zCenter`、`locked`（默认 1，防止游戏按地形重绘覆盖）、
`trackingPosition`、`unlimitedTracking`、空的 `banners` / `frames`、
16384 字节 `colors`；根一层还有 `DataVersion`。`scale` 必须留 0——放大只会让
一个像素覆盖更多方块，把画抹掉。

| 游戏版本 | 地图文件位置 | 计数文件 | `give` 写法 |
| --- | --- | --- | --- |
| 1.20.4 | `存档/data/map_<#>.dat` | `data/idcounts.dat` | `filled_map{map:<#>}` |
| 1.21 ~ 1.21.11 | `存档/data/map_<#>.dat` | `data/idcounts.dat` | `filled_map[minecraft:map_id=<#>]` |
| 26.1 及以上 | `存档/data/minecraft/maps/<#>.dat` | `data/minecraft/maps/last_id.dat` | `filled_map[minecraft:map_id=<#>]` |

26.1 重排了整个存档目录。工具里的版本选择会同时决定 `DataVersion`、文件路径、
ZIP 里的文件名和 `give` 语法，选错版本文件就放不进去。

**编号不要乱填**：存档用计数文件记着「最新地图编号」。编号与已有地图冲突会直接覆盖它；
编号比记录值还大时，游戏下次发新地图仍从小编号排，可能反过来把你放进来的文件覆盖掉。
最稳的做法是先在游戏里用空地图画一张，看它拿到几号，再回到工具用那个编号重新导出替换。

## 数据来源与许可

- 地图基础色表、明暗系数、`.dat` 的 NBT 结构、DataVersion：Minecraft Wiki
  （Map item format / Data version / Java Edition level format）
- 方块 → 基础色：`plonck/palette`（MIT）从 1.21.11 客户端导出的 `blocks.csv`
- `.litematic` 格式：公开的 Litematica Version 6 规格说明（MusicboxMC docs、
  litematica crate 的 format notes）；位打包跨 64 位边界、下标 0 必须是 air
- 算法都是公开的：CIEDE2000（Sharma 等，2005）、Floyd–Steinberg（1976）、
  Atkinson、Bayer 有序抖动。实现均为本项目自写，没有复制第三方代码

## 常见问题

**平铺和阶梯选哪个？** 图标、文字、logo 用平铺（只有一层，最好摆）；
照片、渐变、人像用阶梯（颜色多三倍，但要管高度与支撑）。

**直接写数据还要摆方块吗？** 不用。这个模式把颜色直接写进地图文件，
`give` 出来的地图就能看；施工文件是另外两种模式才需要。

**地图放进去了但游戏里是空白？** 先确认三件事：文件位置和版本对不对、
编号与 `give` 指令一致、进游戏前有没有退出存档（游戏运行时会把它自己的内存数据写回来覆盖）。

**支持基岩版吗？** 不支持，地图数据格式与命令都不同。
